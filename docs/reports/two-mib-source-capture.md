# Two-MiB machine-source capture

The source preparation helper now accepts an explicit repository root and
returns the exact raw templates, generated ATOM text and hashes of both. A
system builder can assemble that captured result without reopening the source
files. The existing one-argument preparation and assembly calls retain their
module-relative root and generated bytes.

```js
const prepared = await prepareTwoMibSources(count, { repositoryRoot });
const built = await assemblePreparedTwoMibProfile(prepared);
// built.bios / built.bootstrap retain their bytes, base and assembly labels.
```

`prepareTwoMibSourcesFromBodies(count, { bios, bootstrap }, { repositoryRoot })`
is the pure equivalent for already captured `Uint8Array` or `Buffer` inputs.
It copies their bytes, rejects shared backing storage and performs the same
existing equate/table generation. The root determines recorded source paths;
this pure helper does not read them.

The result retains `profile`, `biosSource`, `bootstrapSource` and `sourcePaths`.
It adds the absolute `repositoryRoot`, copied `rawSources.bios` and
`rawSources.bootstrap` buffers, and `sourceProvenance` entries for both inputs.
Each entry contains absolute `path`, `rawByteLength`, `rawSha256`,
`preparedByteLength` and `preparedSha256`. Raw hashes cover the original bytes;
prepared hashes cover the UTF-8 bytes sent to ATOM. The prior UTF-8 decoding
behavior remains unchanged, including replacement of invalid sequences in
generated text. Raw provenance does not silently hash that decoded replacement.

Before its first await, `assemblePreparedTwoMibProfile` copies the captured
bodies and verifies their profile, generated text, paths and provenance. Edited
or inconsistent captures reject before temporary assembly files are created.
Later mutations of caller buffers cannot alter the accepted capture. Assembly
still uses private temporary flat ATOM files and the existing layout checks;
no tracked assembly template, relocation scheme or source substitution changed.

## Verification

The new six-test suite checks an alternate root with distinguishable fixture
padding, exact raw/prepared hashes, deleted source paths, mutation after capture
and during pending assembly, offset views, invalid UTF-8, shared backing stores
including a cross-realm buffer, and rejection of altered capture fields. It also
compares all sixteen BIOS and bootstrap outputs with 32 SHA-256 baselines
measured before the edit at `569d51d` with ATOM 0.3.0.

The existing focused BIOS suite passed 26 tests: every configured count's
layout, invalid count rejection and preservation of legacy source artifacts.
No resident code, workspace, runtime memory or output size changed. BIOS remains
1,024 bytes and bootstrap 256 bytes for each count. The captured-source tests
are build/provenance evidence; they do not establish guest execution or hardware
timing.

```sh
node node_modules/vitest/vitest.mjs run \
  test/distribution/two-mib-source-capture.test.mjs \
  --maxWorkers 1 --no-cache --configLoader runner
node node_modules/vitest/vitest.mjs run test/cpu/bios-two-mib.test.mjs \
  --maxWorkers 1 --no-cache --configLoader runner \
  -t 'rejects invalid configured|assembles count|leaves original'
```

The template reads are separate filesystem operations, not an atomic repository
snapshot. A release builder must still verify the captured raw hashes against
its selected source identity. Source capture does not define a descriptor
schema, admit a runtime profile or select release inputs. Those are separate
integration boundaries.
